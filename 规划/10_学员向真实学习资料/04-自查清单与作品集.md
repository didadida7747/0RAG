# 04 · 自查清单与作品集标准

> 打卡计划解决"做什么"，本篇解决"做到没有、怎么沉淀成作品"。
> 三部分：**每月复盘清单 → 每周复盘模板 → GitHub 作品集标准**。建议每周末、每月末各过一遍。

## 一、每月复盘清单（达标才进下一月）

| 月末 | 我应该能做到（主动回忆，不看资料） |
|---|---|
| 第 1 月 | 用 ≤500 字讲清 LLM 工作原理；写出结构化 Prompt 并解释各部分作用；用 API 实现多轮对话 + 流式输出；产出 ≥2 篇笔记/博客 |
| 第 2 月 | 独立做出**完整单 Agent（工具调用 + RAG）**；能定位常见失败；项目已开源 GitHub；写 1 篇实战博客 |
| 第 3 月 | 用 LangGraph 重构 Agent；**做出 1 个 MCP Server**；做出多 Agent 协作 Demo；讲清 MCP 与 Function Calling 区别 |
| 第 4 月 | 做出**生产级 RAG 并跑出评估报告**；实现带长期记忆的 Agent；搭出含人工审核的工作流 |
| 第 5 月 | 完成 **2 个完整项目**（含部署）；2 篇复盘；GitHub ≥2 个高质量仓库；可录 Demo 视频 |
| 第 6 月 | 有自动评估脚本；服务已上线；有成本/性能优化数据；作品集主页 + 个人品牌就绪 |

> 用法：月末逐条自测，**打勾不足 80% 就先补，不盲目赶进度**。能向别人讲明白，才算真掌握。

## 二、每周复盘模板（复制到笔记，周末填）

```markdown
## 第 __ 周复盘（日期：____）
- 本周计划：____
- 实际完成：____
- 本周交付物（代码/笔记/项目，附链接）：____
- 卡住的点 & 怎么解决：____
- 一个本周最大的收获：____
- 下周 3 件最重要的事：
  1. ____  2. ____  3. ____
- 学习时长合计：____ h（目标 10–15h）
```

**每周三条硬纪律**
1. 有输入必有输出：哪怕只跑通一段代码、记一页笔记，不留"只收藏没动手"；
2. 代码进 Git：当天提交，写清 commit；
3. 卡壳超 1 小时就换通道（查官方文档/看评论/问社区），不硬耗。

## 三、GitHub 作品集标准（招聘/竞赛真正看的东西）

### 单个仓库应包含
- [ ] **README**：一句话项目背景 → 解决什么问题 → 功能清单 → 技术栈 → **架构图** → 快速开始（可复制命令）→ 效果截图/Demo 链接；
- [ ] **架构图 / 流程图**（Agent 循环、RAG 流程、多 Agent 协作）；
- [ ] **部署文档**：Docker / 环境变量 / 一键启动；
- [ ] **评估报告**：如 RAGAS 指标、任务成功率、优化前后对比；
- [ ] **可在线体验**的 Demo 链接（或清晰的本地运行步骤）；
- [ ] 配套**复盘博客**链接。

### 作品集整体建议
- **至少 2 个有质量的仓库**：一个偏 RAG/知识库，一个偏 Agent/多智能体（对应打卡第 5 月）；
- 建一个 **作品集主页 README / 个人主页**，把所有项目、博客、联系方式串起来；
- 每个项目都能讲清三件事：**业务场景、技术难点与方案、可量化效果**；
- 录 1 个 1–3 分钟 Demo 视频，比纯文字更直观，可发 B 站/简历附件。

## 四、评审视角的"含金量"自检

| 低含金量（玩具 Demo） | 高含金量（生产级） |
|---|---|
| 单文件脚本、无文档 | 完整目录 + README + 架构图 |
| 只在本机跑通 | Docker 部署 / 在线可访问 |
| 无评估、"感觉能用" | 有评估指标与对比数据 |
| 只调一次 API | 含工具/记忆/RAG/异常处理 |
| 项目雷同、无场景 | 有明确垂直行业场景与差异化 |

## 五、一句话收口

> 知识点会过时、证书只是敲门砖，**真正可迁移、可验证的资产是你 GitHub 上"能跑、有文档、有评估、有场景"的 Agent 项目**。
> 每周用模板复盘、每月用清单验收、每阶段把成果整理进作品集——坚持这套闭环，6 个月后你手里就是一份能直接用于西电竞赛、大创、求职的完整答卷。
