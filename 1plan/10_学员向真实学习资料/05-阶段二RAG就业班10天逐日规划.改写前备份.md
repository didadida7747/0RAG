# 05 · 阶段二 RAG 就业班 · 10 天逐日规划

> 把 48 个技术点排进 10 天（全天集训口径，每天约 7–8h）。
> **排程逻辑**：按依赖关系推进——LangChain 是地基 → RAG 复用 LangChain 组件 → LangGraph 做 Agent 编排（最难，给 3 天）→ 部署收口（要有成品才可部署）。

## 模块天数分配

| 模块 | 技术点 | 天数 | 安排 |
|---|---|---|---|
| LangChain | 10 | 2.5 天 | Day1、Day2 + Day3 上午 |
| RAG | 9 | 2.5 天 | Day3 下午 + Day4、Day5 |
| LangGraph | 12 | 3 天 | Day6、Day7、Day8 |

## 逐日安排

- 10 天很紧，**最容易超时的是 Day4（Milvus 环境）和 Day8（多 Agent 联调）**，预留半天弹性；
- 若落后：部署部分（Day9–10）可只掌握"Dockerfile + Compose 部署自己项目"，Linux 命令边用边查；
- 不要追求每个 API 记牢，**目标是两个能跑、能部署、讲得清的成品**。

## 在校自学版（拉长到 3–4 周）

### A. 必须修正（开课前完成）

1. **Day 4 的 Milvus 环境：先选方案，再开课。** Windows 上有两种路线：

   | 方案 | 做法 | 优点 | 缺点 | 建议 |
   |---|---|---|---|---|
   | **A. Docker 版 Milvus** | Docker Desktop 一键启动 Milvus（Standalone） | 与 Day 9 的 Docker 内容衔接；和真实生产环境最接近 | 占内存较多，需 WSL2 + Docker 正常运行 | **默认选这个** |
   | **B. Milvus Lite（WSL2 里运行）** | 在 WSL2 的 Ubuntu 中 `pip install milvus-lite` | 不用 Docker，文件型，上手快 | Windows 原生直接装兼容性不稳定，必须进 WSL2 使用 | 方案 A 装不上时的备选 |

   > 通俗理解：方案 A 像"租一间带全套设施的办公室"，功能全但要的资源多；方案 B 像"在一个小抽屉里存数据"，轻巧但要在指定的小房间（WSL2）里操作。

   **无论选哪个，Day 0 都要做一次连通测试**，能连上并创建一个空集合（Collection）才算通过。连续 2 小时没通过，就先用 **Chroma** 完成 Day 4 的入库，Milvus 留到 Day 9 之后对照补做。

2. **术语修正：Day 4 的"Milvus DDL/DML"改为"集合（Collection）的创建、数据插入、向量检索"。** DDL/DML 是 SQL 数据库的术语，学员按这个词搜资料会搜到错误内容。Milvus 用的是 Python SDK 调用。

3. **Docker 知识顺序冲突。** Day 4 要用 Docker，但 Docker 要到 Day 9 才教。
   - 在 **Day 0** 增加 1 小时"Docker 入门"：只学 `镜像`、`容器` 两个概念，以及 `docker run`、`docker ps`、`docker stop` 三条命令。
   - Day 9 再深入讲数据卷、网络和 Compose。

4. **在校自学版时间换算修正。** 10 个集训日 × 每天 2–3 个工作日晚上 ≈ 20–30 个工作日，约 **4–6 周**，原文写的"3–4 周"偏短，请改掉。

5. **统一 LangChain 版本。** Day 2 的 Memory、Runtime、Middleware 在新版 LangChain（1.x）中的讲法与旧版不同。开课前在 `requirements.txt` 里写死版本号，并确认课件使用的是同一版本。

### C. 成品验收标准（写进每天的"当天产出"）

**RAG 企业问答（Day 5）**
- 能加载至少 1 份 PDF 和 1 份 TXT 文档；
- 回答附带来源（文件名 + 页码或段落）；
- 对资料中没有的问题能拒答（回复"资料中未找到"）；
- 有一张 10 个测试问题的记录表（问题、期望答案、实际答案、是否通过）；
- README 含运行步骤和截图。

**多智能体客服（Day 8）**
- 能把问题正确路由到至少 2 个专员（例如：订单、退款）；
- 每个专员有独立的提示词或工具；
- 有至少 5 条路由测试用例；
- README 含架构图。

**部署（Day 10）**
- 一条命令 `docker compose up` 能启动项目；
- API Key 通过 `.env` 文件注入，**不写进代码和镜像**；
- 公网访问为加分项，不作为通过条件。

### D. Windows 环境清单（Day 0 增补）

1. **电脑配置检查**：建议内存 ≥ 16GB；硬盘剩余空间 ≥ 30GB（Docker 镜像很占空间）；BIOS 中开启"虚拟化"（Docker 必需）。
2. **安装 WSL2**：以管理员身份打开 PowerShell，执行 `wsl --install`，重启后安装 Ubuntu。
3. **安装 Docker Desktop**：设置中勾选 "Use WSL 2 based engine"，并在 Resources → WSL Integration 中打开 Ubuntu。
4. **Python 虚拟环境**：`py -3.10 -m venv .venv`，激活时若被系统拦截，以管理员身份执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`。
5. **路径与编码**：项目放在纯英文路径下（如 `D:\rag-course`），避免中文路径和桌面深层目录；编辑器统一用 UTF-8。
6. **连通性自检**（Day 0 结束前全部通过）：
   - `docker run hello-world` 能输出成功信息；
   - `python -c "import langchain"` 不报错；
   - Ollama 能成功运行一次本地模型；
   - Milvus（或选定的替代方案）能创建一个空集合。
7. **提前下载本地模型**：Day 0 就把 Ollama 的小模型下载好，避免上课时等待下载。

### E. 安全规则（写进 Day 0 和每日提交要求）

- API Key **只能**放在 `.env` 文件中；
- `.gitignore` 必须包含 `.env`；
- 第一次提交前执行 `git status`，确认 `.env` 没有出现在待提交列表中；
- 如果 Key 不慎提交或泄露，立即在平台后台删除并重新生成。
