## 五、逐日安排

> 每天结构相同：**目标**（一句话）→ **学习要点**（学员要真正理解的问题）→ **动手任务** → **当天产出**（老师检查的依据）→ **常见卡点**。

### Day 1 · LangChain 地基：模型、消息、提示词

**目标**：学会用统一的方式调用不同的大模型。

**学习要点**
- LangChain 解决什么问题：把不同厂商的模型接口统一成一套写法；
- Models：同一段代码切换 DeepSeek、智谱、Ollama，只改配置；
- Messages：System / Human / AI 三种消息各自的角色，以及它们如何组成一次对话；
- Prompts：模板里的变量怎么填，为什么要把"指令"和"数据"分开写。

**动手任务**：写一个脚本，三种模型各回答一次同样的问题，并用提示词模板完成一次结构化问答（如"把一段文字提取成 JSON"）。

**当天产出**：能切换 3 种模型、用模板完成结构化问答的脚本。

**常见卡点**：API Key 没读到（检查 `.env` 是否加载）；Windows 下中文乱码（统一用 UTF-8 保存文件）。

### Day 2 · LangChain：工具、记忆、运行时

**目标**：让模型能"动手"（调用函数），并能记住上下文。

**学习要点**
- Tools：`@tool` 装饰器、`args_schema` 如何描述参数、`tool_choice` 控制模型是否必须调用工具。关键理解：**模型并不执行函数，它只决定调用哪个函数、传什么参数**；
- Memory：多轮对话为什么需要记忆；新版 LangChain 推荐用 LangGraph 的 checkpointer 做短期记忆，**老教程里的 `ConversationBufferMemory` 已过时，不要教**；
- Runtime：运行时上下文（如当前用户 ID）如何传给工具，而不是让模型自己去猜；
- Middleware：只讲概念（调用前后插入日志、限流、人工审批等），实操留到 Day 7。

**动手任务**：写一个对话脚本，带 2–3 个自定义工具（如查天气、算数、查订单假数据），并能记住前几轮的内容。

**当天产出**：一个带工具、有记忆的对话脚本。

**常见卡点**：工具描述写得太含糊，模型不调用或乱调用——这是正常现象，要回头改 docstring 和参数说明。

### Day 3 · MCP 入门 + RAG 原理与文档加载

**目标**：理解 MCP 是什么；理解 RAG 的完整链路；能把多种格式的文档读进来。

**学习要点**
- MCP：Client 和 Server 的关系（像"插座和电器"，统一接口接入外部能力）；
- RAG 全链路：**加载 → 切分 → 向量化 → 入库 → 检索 → 生成**。学员要能用自己的话讲清每一步在解决什么问题；
- Document Loader：TXT、CSV、JSON、PDF 的加载差异（PDF 容易出现乱码和页码丢失，要提前认识到）。

**动手任务**
- 上午：跑通一个现成的 MCP 示例（如时间服务或文件读取），并让模型调用它；
- 下午：用 Loader 读入 4 种格式的文档，打印每份文档的内容长度和元数据；
- 晚上：手绘一张 RAG 流程图，标出每一步的输入和输出。

**当天产出**：MCP 示例跑通；4 种格式文档能加载；一张手绘 RAG 流程图（拍照提交）。

**常见卡点**：PDF 加载后文字顺序错乱（先换一个 PDF 测试，不必纠结）；MCP 依赖装不上（老师提前在 Day 0 验证好 MCP 示例所需的依赖）。

### Day 4 · RAG 核心：切分、嵌入、向量库

**目标**：把文档变成可以检索的向量，并存进 Milvus。

**学习要点**
- Text Splitter：块大小（chunk_size）和重叠（overlap）如何影响检索效果。关键理解：**块太大会混入无关内容，块太小会丢失上下文**；
- Embedding Model：文字如何变成向量，"语义相近"在向量空间里意味着"距离近"；
- Vector Store：为什么需要向量库，而不是普通数据库；
- Milvus：集合（Collection）、字段（Field）、向量维度、索引。用 Python SDK 完成建集合、插入、搜索，**不讲 SQL 的 DDL/DML**。

**动手任务**
- 上午：用两种切分方式处理同一份文档，对比检索结果；
- 下午：启动 Milvus，建集合，写入切分后的文档向量，做一次相似度检索；
- 晚上：把 Day 3 加载的全部文档切分并写入 Milvus，记录每份文档的块数。

**当天产出**：文档成功向量化入库，能用一个问题查出最相关的 3 个文本块。

**Milvus 启动方案（待课程负责人确认，见第九节）**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. Docker 版 Milvus（默认）** | 老师提前准备好官方 `docker-compose.yml`，学员直接启动 | 与 Day 9–10 的容器内容衔接，接近生产环境 | 占内存较多，需 Docker 正常运行 |
| **B. Milvus Lite（在 WSL2 内运行）** | WSL2 的 Ubuntu 中 `pip install milvus-lite`，数据存为本地文件 | 不用 Docker，上手快 | Windows 原生兼容性不稳定，必须在 WSL2 中运行 |

> 通俗理解：方案 A 像"租一间带全套设施的办公室"，功能全但资源占用大；方案 B 像"一个小抽屉"，轻巧但要在指定的房间（WSL2）里操作。

**保底规则**：连续 2 小时没连上 Milvus，就先用 **Chroma**（纯 Python 的轻量向量库）完成本天入库，Milvus 留到 Day 9 之后对照补做。

**常见卡点**：Milvus 启动后连接超时（先看 `docker ps` 容器是否在运行，再看端口是否被占用）；向量维度和 Embedding 模型不一致（建集合时的维度必须与模型输出一致）。

### Day 5 · RAG 召回、模式与成品：RAG 企业问答

**目标**：把 RAG 做成一个能用、能说清来源的问答系统。

**学习要点**
- Retrievers：相似度检索、`top-k` 的取值、MMR（在"相关"和"不重复"之间取平衡）；
- RAG 多种模式：朴素 RAG、查询改写、重排序（Rerank）。**不要求全部实现**，讲清原理，选 1–2 种动手；
- RAG 系统评估：用一张 10 个测试问题的打分表做人工评估（问题、期望答案、实际答案、是否命中来源、是否通过）。自动化评估框架不在本次范围。

**动手任务（下午 + 晚上，做成品）**
- 搭建"RAG 企业问答"：读入资料 → 检索 → 生成回答；
- 回答必须附带来源（文件名 + 页码或段落）；
- 资料中没有的问题，要回答"资料中未找到"，而不是编造；
- 补 README（运行步骤 + 截图）并提交 Git。

**当天产出**：**第一个成品——可问答、标注来源、能拒答的 RAG 企业知识库**（验收标准见第六节）。

**常见卡点**：回答看起来对但没有来源（检查 Prompt 里是否要求引用，以及检索结果是否真正传给了模型）；问题稍微换个说法就答不出（这正是引出"查询改写"的好时机）。

### Day 6 · LangGraph 基础：概念与顺序工作流

**目标**：理解"图"的思路，能把一个多步骤任务写成图。

**学习要点**
- LangGraph 概述：为什么需要它——链（chain）只能一条路走到底，图（graph）可以分支、循环；
- 核心概念：**State**（共享的数据）、**Node**（做事的步骤）、**Edge**（步骤之间的连接）、**StateGraph**（把它们组装起来）；
- 流程编排：编译（compile）后再调用（invoke）的流程；
- 对比 LangChain 链与 LangGraph 图：什么时候用链、什么时候用图。

**动手任务**
- 上午：写一个三步的顺序工作流（如：取输入 → 处理 → 输出）；
- 下午：写一个多输入工作流（多个输入字段汇入同一个 State）；
- 晚上：用一张表对比链与图（写法、适用场景、优缺点）。

**当天产出**：顺序工作流和多输入工作流两个 Demo 能跑通。

**常见卡点**：State 字段没有更新（检查 Node 是否返回了字典，而不是直接修改 State）。

### Day 7 · LangGraph 进阶：分支、循环、ReAct Agent

**目标**：做出一个会自己决定下一步、能循环调用工具的 Agent。

**学习要点**
- ConditionalGraph：条件边如何根据 State 决定走哪条路；
- LoopingGraph：循环的终止条件，为什么必须有"退出条件"，否则会无限循环；
- ReAct 模式：推理（Reason）→ 行动（Act）→ 观察（Observe）的循环。这是大多数 Agent 的基本骨架；
- Middleware 实操：在 Day 2 的概念基础上，给 Agent 加一个调用前的日志中间件。

**动手任务**
- 上午：写一个带条件分支的 Demo（如：判断问题类型，走不同分支）；写一个带循环的 Demo（如：反复检查直到满足条件）；
- 下午：用 LangGraph 搭一个 ReAct Agent；
- 晚上：**用 ReAct 重构 Day 2 的工具助手**，对比两者的代码量和可控性。

**当天产出**：一个会自主推理、能循环调用工具的 Agent，并附一段对比说明（Day 2 与 Day 7 的差异）。

**常见卡点**：循环停不下来（先在图里加一个最大步数限制）；模型不调用工具（检查工具描述，以及 ReAct 节点的条件边）。

### Day 8 · Multi-Agent 与 LangGraph 高级模式：智能客服

**目标**：从零搭一个有路由和多个专员的智能客服。

**学习要点**
- MultiAgent（LangChain 模块的收尾，放在这里讲）：多个 Agent 如何分工、如何交接任务。关键理解：**分工的关键是"谁负责什么"的边界要清楚**；
- Routing：路由节点先判断问题属于哪一类，再交给对应的专员；
- Evaluator-optimizer、Parallelization：**选学**——讲原理、看示例即可，不强制动手。

**动手任务**
- 上午：讲 MultiAgent 概念，然后做 Routing Demo（判断问题类型，分到 2 个分支）；
- 下午：搭"Multi-Agent 智能客服"骨架：一个路由节点 + 至少 2 个专员（如"订单查询"、"退款规则"）。
  - 订单查询可以用假数据（一个模拟工具）；
  - 退款规则**推荐接入 Day 5 的 RAG 知识库**，让两个成品串起来；接不上时，用写死的规则文本代替；
- 晚上：联调，补架构图和 README，准备至少 5 条路由测试用例。

**当天产出**：**第二个成品——多智能体客服**（含路由和分工，验收标准见第六节）。

**常见卡点**：路由总是分错（先看路由节点的提示词，再看专员的职责描述有没有重叠）；联调时间不够（这是 Day 8 最容易超时的地方，见第八节的降级方案）。

### Day 9 · 部署（一）：Linux 与 Docker 基础

**目标**：熟悉 Linux 常用命令；能用 Docker 跑起一个带数据的服务。

**学习要点**
- Linux 概述与常用命令：目录结构、文件操作、进程查看、权限（`sudo`、`chmod`）、环境变量。目标是**能查、能改、能看日志**，不是背命令；
- 软件安装：用 `apt` 安装软件，理解"包管理器"是什么；
- Docker 快速入门：部署 MySQL 容器，理解"镜像 → 容器"的关系；
- 常见命令：`run`（带 `-d`、`-p`、`-e` 参数）、`logs`、`exec`、`stop`、`rm`；
- 数据卷与目录挂载：**容器删了数据还在吗？** 数据卷（volume）和目录挂载（bind mount）的区别。

**动手任务**
- 上午：在 WSL2 的 Ubuntu 中完成一组常用命令练习，用 `apt` 装一个软件；
- 下午：用 Docker 启动 MySQL，建一张表，删掉容器后重新启动，确认数据还在；
- 晚上：练习目录挂载，把本地文件挂进容器里读取。

**当天产出**：能用 Docker 跑起 MySQL 并挂载数据；删除容器后数据依然存在。

**常见卡点**：找不到 Ubuntu 里的文件（先用 `pwd` 确认当前路径）；挂载后容器读不到文件（检查路径是否写成了 Windows 格式，应使用 Linux 路径）。

### Day 10 · 部署（二）：镜像、编排与项目上线

**目标**：把两个项目打包成镜像，用 Compose 一条命令启动。

**学习要点**
- Dockerfile：每一行在做什么，为什么要把依赖安装放在代码复制之前（利用缓存）；
- 自定义镜像：从 Dockerfile 构建镜像，并运行它；
- 容器网络：容器之间用服务名互相访问（如应用容器连接 Milvus 容器），而不是用 `localhost`；
- Docker Compose：用一个 `docker-compose.yml` 同时启动应用和依赖（如 RAG 应用 + Milvus）；
- Linux 项目部署：在 WSL2 的 Ubuntu 中完成整套部署。

**动手任务**
- 上午：为 RAG 项目写 Dockerfile，构建镜像，单独运行并访问；
- 下午：用 Compose 把 RAG 应用和 Milvus 一起启动；再为客服项目写 Compose，在本地跑通；
- 晚上：**总复盘**，整理作品集仓库（README、架构图、部署文档、截图、报错记录）。

**当天产出**：
- **RAG 问答**：`docker compose up` 能在本地启动，访问页面能正常问答；（**必须完成**）
- **多智能体客服**：`docker compose up` 能在本地启动，路由测试通过；（**必须完成**）
- 公网在线访问：**加分项**，不作为通过条件。

**常见卡点**：容器之间连不上（检查网络和服务名）；镜像构建很慢（先配置国内镜像源，或提前构建好基础镜像）；API Key 进了镜像（用 `.env` 文件在运行时注入，并检查 `.dockerignore` 是否排除了 `.env`）。

## 八、弹性与降级方案

| 情况 | 降级做法 |
|---|---|
| Day 4 Milvus 连不上超过 2 小时 | 先用 Chroma 完成入库，Milvus 留到 Day 9 之后对照补做 |
| Day 5 做不完成品 | 保住"能问答 + 标注来源"这两项，拒答和评估表留作课后补充 |
| Day 8 联调超时（最容易超时） | 砍掉 Evaluator-optimizer 和 Parallelization（本来就是选学）；客服先用写死的规则文本，不接 RAG |
| Day 9–10 落后 | 只掌握"Dockerfile + Compose 部署自己的项目"，Linux 命令边用边查 |
| Day 10 公网上线来不及 | 本地 Compose 演示 + 录屏，在作品集中说明；国内云服务器备案可能需要数周，不要指望在课程内完成 |

> 原则：**两个能跑、能部署、讲得清的成品**比全部技术点都摸过更重要。

## 九、需要课程负责人确认的决定

这些是技术和教学上的选择，AI 给出了推荐，但最终由课程负责人决定：

1. **Milvus 启动方案**：默认 A（Docker 版），备选 B（Milvus Lite 在 WSL2 中运行）。见 Day 4。
2. **LangChain 版本**：建议开课前在 `requirements.txt` 中锁定版本号，并确认课件用的是同一版本。Day 2 的 Memory、Runtime、Middleware 在新版（1.x）中的讲法与旧版不同。
3. **Day 8 是否接入 RAG 知识库**：推荐接入，让两个成品串起来；代价是 Day 8 的工作量增加。
4. **在校自学版的周期**：见第十节。

## 十、在校自学版（拉长到 4–6 周）

- 若不是全天集训，按"**1 个集训日 ≈ 2–3 个工作日晚上 + 半个周末**"换算，10 个集训日约需 4–6 周；
- 建议节奏：LangChain 约 1 周，RAG 约 1 周，LangGraph 约 1–1.5 周，部署与收尾约 1 周；
- 可结合短学期、大创或竞赛项目同步推进，把两个成品直接作为项目成果。
